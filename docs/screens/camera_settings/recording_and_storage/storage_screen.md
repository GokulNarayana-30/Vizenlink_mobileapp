# StorageScreen

- **Dart file:** `lib/screens/camera_settings/storage_screen.dart`
- **Route:** `/dashboard/live/:cameraId/settings/storage`
- **Purpose:** Storage config + recorded-clip browsing, merged into one tabbed screen — reached from the "Storage & Recordings" row on [camera_settings_screen.md](../camera_settings_screen.md) (a top-level camera setting, not nested under Video & Display, matching Audio/Danger Zone; the earlier separate "Recording" row is gone — see below). **Merged with a real Recordings tab, then made fully real, both 2026-09-07** (direct user requests: "keep storage recording option same as that app" and "it need to contain local sd storage and sd card present and its capacity, record to sd card toggle each clip duration slider 1 min to 5min" — plus "check my senior app how he have that", which is why this tab's card layout/copy/icons/confirm-on-turn-off behavior deliberately match the sibling `nuraeye-rt` app's own `StorageSettingsScreen` line for line, not just in spirit) — a single `Scaffold`/`AppBar` with a `TabBar` (`Storage` / `Recordings`), not two separate screens, and no more mocked `Camera`-model fields (capacity/health/retention/deletion-history) anywhere in it.
  - **Storage tab**: real. SD-card presence + capacity/free-space and the "Record to SD Card" toggle come from `LocalStorageClient.getStatus()`/`setEnabled()` (`FR-CF-044`) — same client, same card layout/icons/copy, and the same "turning off asks for confirmation, turning on doesn't" behavior as the reference app's screen. **WAN fallback added 2026-09-15** (real gap fixed — `WanLocalStorageClient` existed (`FR-MOB-083`) but was never actually called): both `_load()` and `_applyEnabled()` now retry over WAN (`WanLocalStorageClient.getStatus()`/`setEnabled()`) when the LAN call fails and `connection.thingName` is known, per this app's own LAN/WAN convention — a camera off the phone's current LAN no longer shows "could not load storage status" when it's genuinely still reachable over WAN. Clip duration (STOR-014/015/016) is `RecordingsClient.getClipDuration()`/`setClipDuration()` bounded by `CapabilitiesClient`'s real `recordingClipDurationMinSeconds`/`MaxSeconds` — moved here from [recording_screen.md](recording_screen.md)'s former REC-014/015/016 (that screen is Mode/Schedule only again, to avoid the same feature living in two places); no WAN mirror exists for this one. There's no screen-wide Save button any more — every control here is a real network round trip, applied independently, not a locally-staged value.
  - **Recordings tab**: real, `RecordingsClient`-backed flat list of clips (last 90 days, newest first) with checkbox multi-select + delete — browsing/managing what's on the card, not a second video surface (see STOR-019/STOR-020).
  - A "Recording Mode & Schedule" row (STOR-021) at the top of the Storage tab still opens [recording_screen.md](recording_screen.md) for Continuous/Scheduled/Event-Triggered mode — a distinct feature the reference app doesn't have, kept reachable from here rather than as its own top-level settings row, so "Storage & Recordings" stays the one entry point for everything storage/recording-related, matching the reference app's single-entry-point structure.

## Data model

No `Camera`-model storage fields are read or written by this screen any more (`sdStorageEnabled`, `retentionDays`, `sdCardCapacityGb`/`sdCardUsedGb`/`sdCardHealthPercent`/`sdCardEnduranceRated`, `storageFailure` — all retired from this screen's own use, though the `Camera` model itself may still carry them for other screens/seed data). Everything shown is either `LocalStorageStatus` (`enabled`, `cardPresent`, `capacityBytes`, `freeBytes` — `packages/camera_api`) or the same `RecordingClip`/clip-duration types [recording_screen.md](recording_screen.md) and [camera_live_screen.md](../../camera_live/camera_live_screen.md) already use.

## Recordings tab works over WAN (2026-09-21)

The Recordings tab's clip list now falls back to `WanRecordingsClient.getRecordings()` when the
LAN `RecordingsClient` call fails — the same LAN-first/WAN-on-failure shape this screen's storage
status and enable/disable paths already used. Before this it was LAN-only, so the tab sat empty
off-network even while the Playback tab on [camera_live_screen.md](../../camera_live/camera_live_screen.md)
listed the very same clips over WAN. No element or design ID changed.
