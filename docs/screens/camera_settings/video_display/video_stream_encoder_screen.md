# VideoStreamEncoderScreen

- **Dart file:** `lib/screens/camera_settings/video_stream_encoder_screen.dart`
- **Route:** `/dashboard/live/:cameraId/settings/video-display/video-encoder/stream` — pushed with `extra: (camera, VideoStream)` from a stream row on [video_encoder_screen.md](video_encoder_screen.md) (ENC-019/020/021).
- **Purpose:** The per-stream encoder settings form — one instance per `VideoStream` (`highRes` / `medium` / `low`). Same field set the old single `VideoEncoderScreen` had (resolution, video encoder/codec, encoder profile, frame rate, GOV, quality, bitrate mode, bitrate), now scoped to one stream. State is staged locally and only applied when Save is tapped. The screen reads/writes its stream's config via `camera.encoderConfigFor(stream)` / `camera.copyWithEncoderConfig(stream, config)` (a `StreamEncoderConfig` value object), so it never has to know that `highRes` maps to `Camera`'s top-level encoder fields while `medium`/`low` map to their own objects.
  - **All three streams are real** (2026-09-11) when the camera has a saved connection: `OnvifVideoEncoderClient.getVideoEncoderSettings`/`getVideoEncoderSettingsOptions`/`setVideoEncoderSettings` (ONVIF Media2) were generalized to take a `configToken`, so each stream now addresses its own config (`_configTokenFor(stream)` → `kHighResVideoEncoderToken`/`kMediumResVideoEncoderToken`/`kLowResVideoEncoderToken`, i.e. `VideoEncoderCfg_1`/`_2`/`_3`) instead of only `highRes` having a real client. Load fetches every field plus its per-codec real bounds/choice list on open; `setVideoEncoderSettings` (always sends the full config — no partial-update mode over SOAP) pushes on Save, with `VideoEncoderSettings.token` set to that stream's config token. LAN first for load and save; a WAN retry (`WanVideoEncoderClient`, also generalized to take `configToken`) kicks in only when the LAN call itself fails/times out and `connection.thingName` is known, per `.claude/rules/mobile-app-screen-conventions.md`. Options stay LAN-only on a normal load; only the current-value settings read gets a WAN fallback. Options are cached per-token (`videoEncoderOptions:$configToken`) so the three streams' bounds don't collide in `NetworkAnswerCache`.
  - Falls back to local-only (`simulateCameraSave`) for **any** stream when the camera has no saved connection at all, same as every other settings screen.

## Elements

| Design ID | Element | Type | Notes |
|-----------|---------|------|-------|
| SENC-001 | Screen title (AppBar) | Text | "High-res Stream" / "Medium Stream" / "Low Stream" per `stream` |
| SENC-002 | Save button (AppBar action) | `SettingsSaveButton` (shared widget) | disabled until a field changes or while saving; triggers the full-screen `SavingOverlay` while calling `OnvifVideoEncoderClient.setVideoEncoderSettings` for this stream's config token (real for any stream, retried via `WanVideoEncoderClient` on LAN failure when `thingName` known), or `simulateCameraSave` when there's no saved connection at all; then a "Changes saved" snackbar, or an error snackbar with the button re-enabled on failure. On success, persists via `camera.copyWithEncoderConfig(stream, ...)` through `HomesController.updateCamera` |
| SENC-003 | Reload settings button (AppBar action) | `ReloadSettingsButton` (shared widget) | does a real re-fetch (`getVideoEncoderSettings`/`getVideoEncoderSettingsOptions` for this stream's config token, same LAN/WAN logic as initial load) for any stream with a saved connection; for a camera with no saved connection at all, shows a snackbar explaining there's nothing to reload from yet; disabled while a load or save is already in flight |
| SENC-004 | Reset to Default button | OutlinedButton | top of the scrollable list, right-aligned; resets all fields (SENC-005–012) to this stream's hardcoded default preset (not the camera's own values); marks the screen dirty |
| SENC-005 | Resolution selector | DropdownButtonFormField, or a read-only Text label | a plain label when the camera's `getVideoEncoderSettingsOptions()` reports ≤1 valid resolution for the current codec (the common case on this firmware), otherwise a dropdown of the camera's **own reported `width×height` pairs**, largest first. **Changed 2026-09-21** — this was a fixed `1080p/720p/480p` enum that bucketed reported pixels, so a real 2560×1440 stream displayed as "1080p" and two distinct reported sizes could collapse into one entry. When there is no saved connection the dropdown contains just the current value. |
| SENC-006 | Video encoder selector | DropdownButtonFormField | options H.264 / H.265 — filtered to `availableEncodings` when connected; both shown otherwise. Switching codec forces VBR if the newly-selected codec's `supportsCbr` is false (keeps SENC-011's value inside its own item list) |
| SENC-007 | Encoder profile selector | DropdownButtonFormField | Baseline / Main / High — filtered to the current codec's own `encoderProfiles` when connected; all three otherwise |
| SENC-008 | Frame rate slider | Slider | real min/max from the current codec's `frameRateRange` when connected, else 1–25 fps fallback; loaded value clamped into the active bounds before render |
| SENC-009 | GOV slider | Slider | real min/max from `govLengthRange` when connected, else 10–50 fallback |
| SENC-010 | Quality slider | Slider | real min/max from `qualityRange` when connected (ONVIF quality is typically 1–10), else 1–5 fallback |
| SENC-011 | Bitrate mode dropdown | DropdownButtonFormField | VBR always shown; CBR hidden outright (not just disabled) when the current codec's `supportsCbr` is `false` and connected; both shown otherwise |
| SENC-012 | Bitrate slider | Slider | real min/max from `bitrateRange` when connected, else 32–8192 kbps fallback |
| SENC-013 | Unsaved-changes dialog | AlertDialog (shared, `confirmDiscardOnLeave` in `lib/widgets/navigation_leave_guard.dart`) | shown when leaving (back gesture or bottom-nav tap, via the shared `LeaveGuard` widget) while dirty |
| SENC-014 | Discard button (in SENC-013) | TextButton | discards the change and leaves |
| SENC-015 | Save button (in SENC-013) | FilledButton | saves via `_save()` before leaving |

**Retired 2026-09-11:** `SENC-016` ("Not applied to the camera yet" banner) — removed once Medium/Low became real (see purpose note above); no longer shown for any stream.

While `getVideoEncoderSettings`/`getVideoEncoderSettingsOptions` are in flight (saved connection only, initial open or via SENC-003), the whole screen is blocked by the same `SavingOverlay` used for Save, showing "Loading…" — this also stops the codec/resolution/bitrate-mode fields from briefly showing their fallback choice list before narrowing to the camera's real one. A camera with no saved connection never shows a loading overlay on open (nothing to load).

On successful save, values persist through `HomesController.updateCamera` — reopening reflects whatever was last saved. With a saved connection, that save is a real `SetVideoEncoderConfiguration` call (targeting this stream's config token) and the local copy only updates once the camera confirms it.
